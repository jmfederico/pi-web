# PI WEB 插件式多语言实施计划

状态：实施中。基线为 `feat/i18n-foundation` 的 `ca51d35d`。阶段 0 规则与清单已冻结（`docs/localization-copy-inventory.md`）；阶段 1（插件式资源架构与设置页试点）已实现。本文件用于本地评审；实施时按阶段拆分 PR。

## 目标与边界

目标是让 PI WEB **自己编写的浏览器界面文案**按用户选择的语言显示，同时将非英文词典作为可独立安装、启用和更新的 PI WEB 浏览器插件提供。无语言包、语言包加载失败或词条缺失时，英文界面始终可用。语言切换不刷新页面、不重启或中断会话，也不丢失输入草稿和附件。

覆盖标签、操作、对话框、配置页说明、空状态、通知外壳、无障碍名称与播报、项目自带插件界面，以及日期和数字格式。代码、路径、模型名称、用户输入、会话与工具原始输出、第三方插件原始错误详情保留原文。PI WEB 生成的错误前缀可以翻译，原始详情作为参数展示。静态 PWA manifest 中的安装描述单列为后续范围；运行时插件不能改变浏览器在加载前读取的静态 manifest。

“全部覆盖”的验收范围是：安装相应语言包且插件加载成功后，项目自带网页界面没有未经登记的固定英文文案。离线、插件 manifest 不可用等情况允许英文回退，不承诺翻译任意第三方内容。

## 已确认的基线约束

- `src/client/src/i18n/translate.ts` 静态导入 `en.ts` 和 `zh-CN.ts`；`types.ts`、`locale.ts`、语言下拉框固定为英文和简体中文。
- `src/client/src/plugins/external.ts` 已提供外部浏览器插件的 manifest、模块加载和失败隔离；浏览器独立插件符合 `docs/plugins.md` 的分发方式。
- `src/client/src/plugins/registry.ts` 已有 prepare → start → publish 的贡献生命周期，主题是可复用先例。插件 API 版本为 4；修改 `src/plugin-api.ts` 时必须同步内部类型、声明基线和消费者测试。
- `PiWebApp.registerExternalPlugins()` 只在必需 Terminal 可用后注册普通插件；Terminal 模块导入失败时 `loadExternalPlugins()` 还会提前返回空注册列表。必须单独设计语言包的恢复路径，不能假设新增贡献字段就能覆盖故障界面。
- `PluginAction.title/group/description`、工作区面板标题目前是注册时的静态字符串；设置页及其他 Lit 模板仍有大量直接写入的英文；服务端通知包含完整英文正文。
- `ChatView.ts` 在模块加载时用浏览器默认语言创建日期格式化器；`PiWebApp.ts` 的若干 `guard()` 缓存没有语言依赖。仅触发父组件更新不足以保证每块文字重新渲染。
- 服务端通知有路径依据 `notice.message` 文本匹配。转换服务端文案前须改为稳定标识匹配，防止改变业务行为。

## 设计契约

1. **核心默认文案。** 核心保留英文默认词典，并由其键定义核心文案类型。语言包只提供额外语言；不将完整中文词典编译进主应用。词条以稳定的命名空间和键标识，例如 `core.settings.general.heading`、`plugin.git.openFile`。
2. **语言包贡献。** 在公开与内部 `PluginContributions` 增加可选 `locales` 数组。每项包含本地 `id`、标准语言标签、该语言的自称、可选浏览器标签别名、命名空间及 `messages` 字符串映射。首版仅接受纯文本；禁止把翻译字符串当 HTML 注入。动态名称、路径和数值经参数传入，保持 Lit 的文本转义。
3. **插件所有权。** 网关本地的语言包可翻译全局界面；远程机器的语言贡献不能随机器切换改变全局语言。核心和项目自带插件按命名空间提供英文默认文案。第三方插件可以声明自己的默认文案并使用公开的本地化服务；未接入的第三方插件继续显示其原文。
4. **冲突与兼容。** 对同一 `(locale, namespace, key)` 的重复提供使用确定的校验失败，而非静默覆盖。贡献在插件成功启动后发布，失败或宿主销毁时撤销。旧插件在新宿主中继续可用；新语言包声明最低宿主版本，旧宿主可能忽略新字段，文档需说明。
5. **语言状态。** 分开保存 `preference`（Auto 或用户显式语言）与 `effectiveLocale`。语言包尚未加载、被禁用或失败时保留用户选择并显示英文；语言包恢复后自动采用原选择。Auto 按 `navigator.languages` 顺序匹配已安装语言，然后回退英文；同源标签页同步设置。资源发布或撤销即使没有改变语言标签，也通知所有订阅者。
6. **公开查询。** `t(key, params)` 在有效语言中查找词条，缺失时逐条回退英文；开发环境对缺失键、参数不匹配和重复键给出可定位的诊断。为浏览器插件提供可读取当前语言、翻译、订阅变化的公开服务，避免插件导入未公开的核心内部模块。命令、标题等已注册对象在显示时解析文字，保留稳定 ID、快捷键和业务回调。
7. **格式化。** 日期和数字由当前有效语言驱动 `Intl`；切换语言时重建或按语言缓存 formatter。复数与富文本在第一次实际遇到相应文案时增加受约束的消息结构；不把 HTML 放进词典。

接口草案（字段名在首个 PR 中经测试固定）：

```ts
interface LocaleContribution {
  id: string;
  locale: string;
  label: string;
  aliases?: readonly string[];
  namespace: string;
  messages: Readonly<Record<string, string>>;
}

interface PluginContributions {
  // 现有 actions、workspacePanels、workspaceLabels、themes、themePairs 保持兼容
  locales?: readonly LocaleContribution[];
}
```

## 阶段 0：建立文案清单和验收口径

**实施。** 以 `src/client/src/components/`、`controllers/`、`plugins/core/`、`pi-web-plugins/`、浏览器显示的共享 helper，以及服务端状态/通知为入口，逐项登记英文默认文案、来源、显示组件、命名空间、参数和排除理由。覆盖普通文本、属性、标题/描述、空状态、提示、无障碍文字、动态拼接、日期数字和服务器推送。不要用单个正则扫描结果冒充完整清单：需结合组件渲染路径与 UI 巡检。冻结稳定键命名、重复资源规则及英文回退行为。

**验收。** 清单覆盖设置、导航、项目/工作区/会话、聊天、命令面板、弹窗、通知、模型与认证、六个项目自带浏览器插件。每个被排除的字符串有理由；业务 ID、路径、代码和用户内容不被误列为可译文案。清单能标明首个 PR 与后续 PR 的归属。

## 阶段 1：首个 PR——外部语言包驱动设置页

**实施。** 在 `src/plugin-api.ts`、`src/client/src/plugins/types.ts`、`registry.ts` 中增加语言贡献的验证、快照、发布与读取；通过现有外部 manifest 和模块加载器验证真实浏览器插件。修改 `i18n/types.ts`、`locale.ts`、`translate.ts`、`controller.ts`、`PiWebApp.ts` 和 General 设置面板，保留英文默认词典，语言选项由注册资源生成。将当前 `zh-CN.ts` 的翻译移入独立的可安装浏览器语言包；主仓库测试可使用小型假语言包夹具，不把完整中文包回填核心。同步 `src/plugin-api.test.ts`、`test-fixtures/plugin-api-baseline/`、外部插件消费者/打包测试、`docs/localization.md`、`docs/plugins.md` 与用户可见变更的 changeset。

**Terminal 故障处理。** 在该 PR 中明确验证 `required`、`recovery-disabled` 和 Terminal 模块导入失败三种路径。若主 manifest 仍可用，应让经过服务端标记、且不依赖 Terminal 的语言包先于普通插件独立注册；不得为了加载语言包而无条件开放所有普通插件。标记须在包声明、服务端 manifest 和浏览器解析中一致校验。若 manifest 本身不可取得，保持英文回退并给出可观察的加载失败。此处需要触及插件发现/manifest；只改 Registry 不够。

**自动验收。** Registry 单测覆盖成功发布、同语言不同命名空间、重复键、非法标签、启动失败回滚、远程贡献隔离、dispose 清理。LocaleStore 纯测试覆盖安装前显式偏好、资源到达后生效、资源消失后英文回退、Auto 顺序（`["en-US", "zh-CN"]` 选英文）、缺词和插值、跨标签页与存储不可用。外部加载集成测试使用独立浏览器插件夹具，证明词典来自插件模块而不是静态导入；Terminal 故障路径仍可显示可加载的语言包。

**手工验收。** 未安装语言包时只有 Auto/English 且页面可用。安装独立中文包、刷新后出现简体中文；切换即刻翻译 General 标题、说明、操作和语言卡片。保留配置表单输入；刷新和另一个标签页保持选择；禁用或移除包后显示英文但不抹除已保存的 `zh-CN` 偏好，恢复包后重新显示中文。插件加载失败不阻止设置页和会话继续使用。

## 阶段 2：核心浏览器界面逐区迁移

**实施。** 按独立 PR 迁移：①剩余设置页和配置说明；②导航、项目/工作区/会话、空状态和操作菜单；③聊天、输入框、提示、认证/模型/命令对话框；④通知、无障碍标签与播报。每个直接写入的产品文案改用稳定键，动态部分作为参数。`PluginAction` 和工作区面板等注册时存储稳定的文案引用或默认英文，在 `getActions()` 等显示边界按当前语言解析；搜索使用当前显示语言，不改快捷键、URL、插件 ID。为 `guard()` 添加语言或资源版本依赖，对独立 Lit 组件使用 `LocaleController`，避免重建正在编辑的表单、聊天会话或附件状态。

**验收。** 每个 PR 至少覆盖该区域的可见文字、标题/placeholder、按钮状态、错误前缀和 ARIA/播报；英文与中文快照或行为测试均通过。语言切换时打开的对话框、命令搜索、配置草稿、聊天输入与附件不丢失，会话不重连。命令在中文下可按中文标题搜索；切回英文仍保留相同操作 ID 与快捷键。对 `guard()` 下的导航/工作区区域做真实组件边界测试，证明语言改变后会刷新。

## 阶段 3：项目自带插件与第三方接入

**实施。** 迁移 `pi-web-plugins/{terminal,files,git,info,updates,workspace-tasks}` 的宿主编写文案，涵盖贡献标题、面板文本、操作、空状态、提示和无障碍文字。让公开插件上下文提供有生命周期的本地化服务（当前语言、查询、订阅），使第三方插件可以选择提供自己的英文默认文案和额外语言资源。其订阅在插件 dispose 时清理；插件自绘内容由插件负责重绘。各插件使用自己的命名空间，语言包可贡献相应命名空间的译文。

**验收。** 六个自带插件在中英文切换后更新标题和打开的面板；关闭/重新打开后不残留旧语言。没有本地化支持的第三方插件照常加载并显示原文。公开 API 消费者测试在 NodeNext 与 Bundler 模式编译通过；插件停用和宿主销毁后无残留订阅或词典。

## 阶段 4：服务端自有提示、格式化与完整覆盖

**实施。** 将核心服务端状态/通知的项目自有文案改为稳定 `code/id + params + 英文后备文本`，浏览器优先翻译已知代码，未知/第三方消息显示原文。先把依赖 `notice.message` 相等的业务匹配改为稳定标识，避免翻译改变逻辑。Pi Web 状态消息、浏览器错误前缀和会话警告分别审查；不翻译来自工具、模型或第三方的原始详情。让 ChatView 等日期/数字格式随有效语言变化。对复数、富文本需求加入可验证的规则，确保不会将译文作为 HTML 执行。

**验收。** 同一条已创建的项目自有通知在切换语言后更新显示，不变更 id、去重、严重级别、关闭行为和原始诊断详情；旧服务端仍发送英文时客户端正常显示。通知出错路径的既有回归测试通过。时间和数字切换后立即按新语言显示，无需刷新。若修改 `src/server/sessiond.ts`、session daemon 协议或其专有加载代码，验收记录必须注明手动重启 sessiond；仅浏览器/UI 改动无需中断会话。

## 阶段 5：终验与维护机制

**实施。** 对阶段 0 清单逐项完成双语 UI 巡检，并用静态扫描持续找新增的固定英文 UI 字符串；对例外建立明确清单。自动校验所有核心默认键、占位符、语言包元数据和重复项；允许第三方及旧语言包缺少新键并回退英文。文档说明安装、切换、卸载、降级、键版本兼容和贡献冲突。静态 PWA manifest 的本地化作为独立议题评估；只有获得服务端动态资源方案后才纳入“全部文字”验收。

**终验清单。**

- [ ] 独立语言包可安装、启用、禁用、移除与升级；主项目构建产物不含完整中文词典。
- [ ] 核心与六个自带插件的清单项目均能以中文显示；缺词逐条回退英文；第三方原始文本保留。
- [ ] Auto 尊重浏览器语言顺序；显式偏好持久化；多标签同步；语言包晚到、故障与恢复表现确定。
- [ ] 无刷新切换不损失草稿、附件、配置输入、对话框状态、快捷键与活动会话。
- [ ] 服务端自有通知翻译后仍保持匹配、去重、关闭和诊断语义；日期、数字、ARIA 与播报按当前语言更新。
- [ ] 桌面、窄屏和 PWA 模式完成手工巡检；关键屏幕无未经登记的固定英文文案。
- [ ] `npm run verify`、`npm run build`、公开 API/打包 smoke 与外部浏览器插件加载测试通过；任何未运行项目如实记录原因。
- [ ] 文档、changeset、公开 API 声明基线和独立语言包兼容版本说明一致。

## 建议的验证命令与执行顺序

改动当次先运行最窄的 Vitest 文件，例如 `npm test -- --run src/client/src/i18n/locale.test.ts`、Registry/外部加载测试和对应组件测试；公共类型或来源文件改动后运行 `npm run typecheck`。阶段完成后运行 `npm run verify` 与 `npm run build`；发布接口变化时执行 `npm run smoke:package-install` 和公开 API 消费者检查。浏览器手工检查需使用真实安装的独立语言包，而非把中文源码编入 Vite 主包。每次验收都记录命令、退出码和手工复现结果。

## 本计划的完成判定

阶段 1 通过，只能声明“插件式资源架构与设置页试点完成”。阶段 5 的终验全部通过，才能声明“PI WEB 自有浏览器界面文字完成插件式多语言支持”。这两个结论分别对应作者允许的首个小 PR 与后续渐进 PR，不把未覆盖区域误报为已本地化。
