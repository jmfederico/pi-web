Foundations

Calm, technical, and readable. Use whitespace and type weight to establish hierarchy; reserve accent color for actions, orientation, and meaningful state.

Overline · context, not a heading

A section within the task

Body text explains the next decision. Emphasis highlights the important part. Use monospace for commands and identifiers, not ordinary prose.

Supporting text stays readable. A lower visual priority must not make essential guidance disappear.

  • Page title: one h1, scaling from 2.2rem to 2.9rem on documentation pages. The larger homepage hero is a separate composition.
  • Reading rhythm: 1rem body text, 1.65 line height, and a reading measure around 68ch.
  • Type: IBM Plex Sans for reading; IBM Plex Mono for the brand, code, and technical labels.
  • Surfaces: the page canvas, a quiet inset surface, and a restrained panel. Avoid nested decorative cards.

Use semantic theme tokens from styles.css rather than page-specific colors. Layout belongs to the page; reusable control styling belongs to the shared stylesheet.

Accessibility checks

  • Use Tab and Shift+Tab to reach navigation, copy, the read-only fields, and the disclosure. Focus must remain visible and unobscured.
  • Disabled buttons and inputs stay out of the tab order. An unavailable link has no destination, not a pretend href="#".
  • Inspect both themes, narrow screens, and zoom. Text must wrap; code may scroll within its own container.
  • Keep section links and native details usable without JavaScript. Clipboard and theme switching are enhancements.
  • Use real screenshots to show the interface and semantic diagrams to explain processes. Match screenshots to the page’s light or dark theme, including full-size previews; do not add autoplay or independent screenshot theme controls.
