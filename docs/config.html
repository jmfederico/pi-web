Scope: “Machine” means the selected machine in Fleet. “Gateway” means the machine serving your browser. “Project” means all workspaces in that repository.

Restart: “Sessiond” means the session daemon. Restarting it can interrupt active sessions. A web/API restart or browser reload is not a substitute.

Config files & precedence

Custom config paths: service commands and recovery

start, restart, and doctor use the config path saved in the installed services for readiness checks unless the caller supplies a nonempty PI_WEB_CONFIG override. doctor checks the managed setup, not every custom runtime environment.

Custom config path: situation → action
Situation Behavior / action
Use the installed config Run pi-web start, pi-web restart, or pi-web doctor normally.
Override the path for one command Supply a nonempty PI_WEB_CONFIG when invoking that command. This does not rewrite service definitions.
Change the managed service config path Run pi-web install --config /path/to/config.json to regenerate both web/API and sessiond service definitions.
Upgrade from an installation that set the path only for the web service Rerun that same install command so both services use the same config.
systemd cannot verify the loaded service environment The command fails rather than guesses if manager state is stale, the loaded fragment differs, or a PI WEB-managed environment value cannot be verified. Managed Environment= values (currently PI_WEB_CONFIG) must match the installed definition; unrelated variables are ignored. Drop-ins that leave managed values unchanged are allowed.
systemd uses EnvironmentFile= Accepted with a nonfatal warning. File contents are not included in systemctl's Environment property and PI WEB does not inspect them, so config overrides in those files cannot be verified.
launchd has an old config path or a label loaded from another plist start and doctor fail. restart reloads installed plists and can repair stale loaded state.

Use the selectors in chat or Settings → Keyboard. Pi defaults and PI WEB shortcuts live in different configuration files.

Default selection and shortcut rules
  • Model/thinking stars change new-session defaults, not the current session. Resumed sessions keep saved choices.
  • Project Pi settings, explicit startup choices, and per-model thinking settings can override defaults. If the default model is disabled, startup falls back to the first enabled model.
  • mod means Ctrl or ⌘. App shortcuts support sequences; composer send bindings support one combination only.
  • Unassigned Enter/Shift+Enter insert newlines; Enter accepts a selected completion first. null disables keyboard submission, not the send button.
  • Existing browser-local Enter preferences remain the fallback until a composer binding is configured. Reset restores that fallback.

pathAccess.allowedPaths		 Machine + project [] External roots the file explorer and absolute @ completions can list/read. Next request; refresh open views

uploads.defaultFolder		 Machine + project .pi-web/uploads Default folder for Upload dialogs and Files-panel drops. New dialogs / batches after config refresh

External paths are not an agent sandbox. The allowlist controls PI WEB browser/API file exposure, not the underlying agent’s or OS user’s permissions.
Path formats, overwrite behavior, and folder rules
  • External roots: existing directories using absolute paths or ~, such as /opt/reference, ~/SDKs, or Windows absolute paths on Windows hosts. Relative roots are not supported; symlink escapes are rejected.
  • Upload/attachment folders: nonempty workspace-relative paths. Absolute paths and .. traversal are rejected; repeated separators and backslashes are normalized.
  • Uploads: create parent folders; existing files are preserved unless overwrite is enabled in the review dialog. Direct drops never overwrite.
  • Upload dialog only: clear the destination field to upload that batch to the workspace root.
  • Attachments API: an explicit per-request folder overrides the configured default.

Session daemon

Edit capability toggles in Settings → Session daemon. Timeout and environment-facts settings can be edited in machine config.

Agent capabilities and dialogs
Setting Applies to Default What it changes Apply / restart
Independent sessions
spawnSessions		 Machine true Expose spawn_session so agents can start independent sessions. Sessiond restart
Tracked delegation
subsessions		 Machine true Expose tracked-child tools. Also requires spawnSessions. Sessiond restart
Question forms
askUser		 Machine true Expose ask_user so agents can post browser forms. Sessiond restart
Extension dialog timeout
extensionDialogsTimeoutMs		 Machine 300000 (5 min) Cancel unanswered extension dialogs after this interval; 0 waits forever. Sessiond restart
Environment facts
environmentFacts		 Machine true Include PI WEB nesting and deployment facts in session system prompts. Sessiond restart
Independent sessions vs. tracked subsessions
  • Independent: fire-and-forget work in a workspace of the same project; output is not returned to the parent.
  • Tracked: work in the parent’s working directory; completion wakes the parent and makes output available. No polling needed.
  • Model: both tools accept an exact provider/model-id; otherwise they inherit the parent’s model. Thinking level is inherited and clamped to model capabilities.
Question forms and extension dialogs are different
  • Question forms: up to 20 questions, up to 12 choices per question, custom text, and optional answers. An ordinary chat message cancels an open form; a new form supersedes the old one.
  • Persistence: an open question form survives browser/web restarts while its owning session daemon remains running.
  • Extension dialogs: always supported, independently of askUser. The sooner of the extension’s timeout and the configured daemon timeout wins.
  • Timeout result: false for confirmation; undefined for selection/text input.

After installing or updating a Pi package
Package contains Apply the change
Skills, templates, themes, ordinary extensions Type /reload in each idle session on the target machine.
A PI WEB server plugin (serverModule) Manually restart sessiond, then reload the browser.
A global extension that registers/configures model providers Manually restart sessiond. /reload does not rebuild provider registration.
Recover from a broken server plugin

Run on the affected machine. These commands edit config without loading plugin code. Add --config /path/to/config.json for a custom config.

Offline plugin recovery
Command Effect
pi-web plugins disable <plugin-id> --restart Persist disablement; rejects required Terminal.
pi-web plugins safe-start show Inspect safe-start state.
pi-web plugins safe-start set bundled-only --restart Skip external server packages; keep bundled plugins.
pi-web plugins safe-start set none --restart Skip all server plugins, including Terminal; keep diagnosis/Settings surfaces.
pi-web plugins safe-start clear --restart Restore normal configured discovery.

Restart caution: --restart acts only for a recognized safe installation and can interrupt sessions. Config is saved first; follow manual guidance if restart fails.

Server plugins are trusted in-process code, not crash-isolated. Plugin guide →

Fleet compatibility and unavailable plugin UI
  • Upgrade the gateway and target together; mixed-version plugin operation is unsupported.
  • Restart updated web/API processes and target sessiond, then reload the browser.
  • A paired UI is withheld when its package/settings do not match running server code, or the server plugin is unhealthy/incompatible.

Storage locations

These are environment variables, not JSON config keys. Changing a path does not migrate existing data.

State and storage paths
Setting Applies to Default What it changes Apply / restart
PI WEB state
PI_WEB_DATA_DIR		 PI WEB machine ~/.pi-web Registries, plugins, daemon socket, and session archives. Stop services before switching; then restart
PI_WEB_PROJECTS_FILE Web/API + sessiond $PI_WEB_DATA_DIR/projects.json Override the projects registry file. Web/API + sessiond restart

PI_CODING_AGENT_DIR		 Sessiond ~/.pi/agent Auth, models, settings, Pi packages, and default session storage. Sessiond restart
PI_CODING_AGENT_SESSION_DIR Sessiond <agentDir>/sessions/<encoded-cwd> Override active session storage separately from other Pi state. Sessiond restart
Changing directories or running a second instance
  • State migration: a new PI WEB data directory starts with empty registries and no archives. Stop PI WEB before copying state. For archives, copy both archived-sessions.json and archived-sessions/.
  • Second instance: use a distinct data directory, daemon endpoint, and web port. One live session daemon owns each data directory.
  • Agent state: uses the bundled Pi SDK’s data layout. PI WEB does not convert profiles or move PI WEB-managed archives when the agent directory changes.
  • Active path: sessiond keeps the agent directory resolved at startup. Web/API-only restarts do not change it.
Environment inherited by agent processes
  • Agent shells, terminals, and child sessions inherit the daemon environment, including its resolved Pi state paths.
  • NODE_ENV and PORT are removed from the environment given to agent processes.
  • PI_WEB_SESSION=1 marks nested processes. Inherited PI_WEB_* values still point to the live hosting instance.
  • Do not restart the hosting session daemon from inside an active session you need to preserve.

Offline / skip-check flags: unset or clear them to turn them off. The strings false and 0 still enable them.

Project trust: which resources load?
Trust decisions, in priority order
Condition Result
No trust-requiring project resources Load normally.
Global Pi extension decides via project_trust Use that decision.
Saved decision in trust.json Use the saved decision; set through the Pi CLI trust prompt or workspace toggle.
No decision; defaultProjectTrust=always Load project resources.
No decision; defaultProjectTrust=never or ask Skip project resources; PI WEB has no browser trust prompt.
Catalog refresh timing and failures
  • Freshness: Pi treats catalogs as fresh for four hours, so most hourly checks make no network request.
  • Login/logout: refresh immediately, bypassing the freshness window (except in offline mode).
  • Timeout: 60 seconds. Timeout or unreachable provider gets one retry after five minutes; an HTTP error waits until the next scheduled refresh.
  • Failure: retain the last successful catalog and log the problem.
  • While refreshing: session startup can briefly wait on shared runtime state. The activity line reports concurrent refreshes.
Provider safety and logging
  • Provider registrations/configuration are a startup snapshot. /reload cannot rebuild it.
  • Accepted model-list updates are machine-wide; if two workspaces register lists for one provider, the last registration wins.
  • Model entries can override provider URLs/headers. Pi extensions remain trusted code; this is not a security boundary.
  • Provider decisions are recorded in daemon logs without credentials/configuration, not browser notifications.

Hook contract
Item Behavior
Location Relative to the workspace where the removal command runs—normally the project’s main workspace.
Argument One absolute path: the workspace being removed.
Success (0) Continue with workspace removal.
Failure (nonzero) Block removal; keep the workspace on disk.
