Scope: “Machine” means the selected machine in Fleet. “Gateway” means the machine serving your browser. “Project” means all workspaces in that repository.

Restart: “Sessiond” means the session daemon. Restarting it can interrupt active sessions. A web/API restart or browser reload is not a substitute.

Web search in fresh Pi profiles

Fresh profiles get free web search and page fetching through Parallel Search MCP, with no account or API key. Anonymous search uses Fast mode. The default connects on the first agent prompt. Ask the agent to search the web or read a URL; Pi's tool_search discovers mcp__pi_web_default_search__web_search and mcp__pi_web_default_search__web_fetch before calling them. Search queries and fetched URLs are sent to Parallel when those tools run. Free-tier usage limits apply, and each request has a 30-second timeout.

The default applies only when the active Pi agent directory has neither mcp.json nor mcp-auth.json, the workspace has no .pi/mcp.json, and no extension has registered an MCP server. If an extension registers another server during the session, PI WEB withdraws its own default and leaves the explicit server in place. Existing files, including empty, invalid, unreadable, or disabled configurations, never trigger a fallback. PI WEB does not write or replace MCP settings or credentials. An untrusted workspace file suppresses the default too; Pi still decides whether to load it.

To opt out persistently, create mcp.json in the active Pi agent directory (~/.pi/agent by default, or PI_CODING_AGENT_DIR) containing:

{ "mcpServers": {} }

Keep an existing file and edit it instead of replacing it. You can also disable the MCP built-in with "extensions": ["-builtin:mcp"] in Pi settings. Built-in replacements, tool permissions, and cancellation continue to apply. /mcp reports status; disabling an extension-registered server there lasts for the current session only. Saved configuration changes apply to new sessions or idle sessions after /reload.

Loading this update requires a manual session-daemon restart, which can interrupt active sessions. A browser reload or web/API restart does not load session-runtime changes. See the Markdown reference.

Custom config paths: service commands and recovery

start, restart, and doctor use the config path saved in the installed services for readiness checks unless the caller supplies a nonempty PI_WEB_CONFIG override. doctor checks the managed setup, not every custom runtime environment.

Custom config path: situation → action
Situation Behavior / action
Use the installed config Run pi-web start, pi-web restart, or pi-web doctor normally.
Override the path for one command Supply a nonempty PI_WEB_CONFIG when invoking that command. This does not rewrite service definitions.
Change the managed service config path Run pi-web install --config /path/to/config.json to regenerate both web/API and sessiond service definitions.
Upgrade from an installation that set the path only for the web service Rerun that same install command so both services use the same config.
systemd cannot verify the loaded service config The command stops. Reinstall services with the intended config path and reload the service manager before retrying.
systemd uses EnvironmentFile= Accepted with a warning; config-path overrides in that file cannot be verified.
launchd has an old config path or a label loaded from another plist start and doctor fail. restart reloads installed plists and can repair stale loaded state.

Default selection and shortcut rules
  • Model/thinking stars change new-session defaults, not the current session. Resumed sessions keep saved choices.
  • Project Pi settings, explicit startup choices, and per-model thinking settings can override defaults. If the default model is disabled, startup falls back to the first enabled model.
  • mod means Ctrl or ⌘. App shortcuts support sequences; composer send bindings support one combination only.
  • Unassigned Enter/Shift+Enter insert newlines; Enter accepts a selected completion first. null disables keyboard submission, not the send button.
  • Existing browser-local Enter preferences remain the fallback until a composer binding is configured. Reset restores that fallback.

App shortcuts do not start with unmodified or Shift-only keys while editing text. Avoid conflicting bindings and browser-reserved combinations. New bindings are saved in gateway config.

Theme defaults and device choices

In Settings → General → Theme, choose a theme and Auto mode, then:

  • Use on this device saves a choice for this browser only.
  • Set as default shares a default without replacing existing device choices.
  • Use the default clears this browser’s override.

Device choices take precedence over the configured default, then the built-in default (PI WEB Dark with Auto on). Auto follows the device’s light/dark preference for paired themes; unpaired themes stay selected. Unavailable themes temporarily fall back to Classic without erasing the choice.

The default belongs to the gateway, not a project or remote machine. Changes apply after settings save or browser config refresh, with no service restart.

{ "defaultTheme": { "themeId": "themes:pi-web-dark", "auto": true } }

Use a theme contribution ID rather than a display name. Built-in IDs are themes:pi-web-dark, themes:pi-web-light, and themes:classic.

Path formats, overwrite behavior, and folder rules
  • External roots: existing directories using absolute paths or ~, such as /opt/reference, ~/SDKs, or Windows absolute paths on Windows hosts. Relative roots are not supported; symlink escapes are rejected.
  • Upload/attachment folders: nonempty workspace-relative paths. Absolute paths and .. traversal are rejected.
  • Uploads: create parent folders; existing files are preserved unless overwrite is enabled in the review dialog. Direct drops never overwrite.
  • Upload dialog only: clear the destination field to upload that batch to the workspace root.
  • Attachments API: an explicit per-request folder overrides the configured default.

Session naming model and token budget

Use Settings → Session daemon → Session naming on the selected machine. The naming model button opens a searchable list of that machine’s available models; choose Use session model to remove the model override. No active session is required. Refresh settings to reload the list after configuring a provider. Naming defaults to the session’s model and 24 tokens, including for reasoning models. It does not change the conversation’s model.

{ "sessionNaming": { "model": "provider/model-id", "maxTokens": 2048, "thinkingLevel": "off", "timeoutMs": 90000 } }

All overrides are optional. Omit model to use the session model; omit maxTokens to restore 24. The model uses that machine’s catalog and configured credentials. The budget must be a positive integer; providers may count reasoning against it. It does not control title length.

thinkingLevel defaults to minimal. Supported values are off, minimal, low, medium, high, xhigh, and max. Choose off to disable optional reasoning where supported, while keeping a positive token budget for the title. Models and providers may limit or map levels; off cannot disable mandatory reasoning. Naming settings do not change the conversation’s thinking level.

timeoutMs sets the total naming-request timeout, including gateway queueing, model loading, and generation. It defaults to 10000 (10 seconds). Use a positive integer in milliseconds, up to 2147483647; Settings displays seconds. Increase it for local models that need time to load. Clearing the UI field restores 10 seconds. This is a total wall-time limit, not an idle timeout, and has no environment-variable override.

Saved model, budget, thinking-level, and timeout changes apply to the next naming request without a restart or reload. Existing names and in-progress naming requests are unchanged. Agent permission changes in the same panel still require a session-daemon restart. Naming failures use the first-message fallback and are recorded in daemon logs.

Independent sessions vs. tracked subsessions

Independent sessions run in a workspace of the same project without returning output to their parent. Tracked subsessions run in the parent’s working directory and return results automatically; the parent can keep working or wait for them. Delivered results are not automatically repeated, but remain available for review.

Agent-created tracked subsessions are collapsed under their parent. Use Agent subsessions to expand them. User-created forks and clones, unknown-origin sessions, children without an available parent, and independent sessions remain visible.

New sessions inherit the parent’s model and thinking level unless another model is requested, for example with a #provider/model-id prompt reference. Thinking levels are limited to what the chosen model supports.

Question forms and extension dialogs are different

Agents can ask questions with choices or free-text answers. You may leave questions unanswered; partial submissions are confirmed before sending. Answering or skipping resumes the agent.

Forms are saved in the conversation and survive restarts. Only a form at the end of the active conversation is open; answering, skipping, or sending another message closes it. Earlier forms remain expandable for read-only review. Returning the conversation to a question reopens it; archived conversations remain read-only.

Extension dialogs are always supported, independently of askUser. The sooner of the extension’s timeout and the configured daemon timeout cancels an unanswered dialog.

Saved ≠ active: Settings shows desired and active plugin state. A server plugin can remain active after you disable it until sessiond restarts.

Project plugin settings: scope, merge, and restarts

Supporting server plugins, including Git, accept plugins.<id>.settings in <project>/.pi-web/config.json at the registered project’s path, not in individual worktrees. Project top-level keys override global settings; nested objects are replaced rather than deep-merged. Plugin enablement stays global.

After changing global or project server-plugin settings, manually restart the target session daemon, then reload the browser. A browser reload, web/API restart, or Pi’s /reload is insufficient. The daemon restart can interrupt sessions and terminals; finish important work and restart from outside its hosted sessions.

Git worktree discovery hooks: opt out

plugins.git.settings.workspaceDiscoveryHooks enables automatic worktree discovery on supported Git builds (Git 2.54+). It defaults to true and preserves existing hooks. See Automatic Git worktree discovery.

To opt out, merge this into machine config or the registered project’s .pi-web/config.json:

Git hook opt-out
{
  "plugins": {
    "git": {
      "settings": {
        "workspaceDiscoveryHooks": false
      }
    }
  }
}

Project values override the machine default. Changes require a manual session-daemon restart. Disabling hooks leaves the Git plugin and ordinary workspace discovery available.

Git worktree discovery when running multiple instances

Most installations need no changes. Docker dev automatically uses dev to keep its worktree notifications separate from production; production keeps its existing behavior.

For a custom setup where instances share a PI WEB data directory, set PI_WEB_INSTANCE_NAMESPACE=dev in the dev session daemon’s environment and leave it unset in production. Use a different name for each additional instance: 1–32 letters, digits, underscores or hyphens, starting with a letter or digit.

Restart the affected daemon to apply the change; for Docker, recreate the affected containers. This interrupts active sessions and terminals, so finish important work first. This setting separates Git notifications only; separate data directories are still recommended for independent instances.

Keep the name stable. If you need to retire a name, disable discovery hooks while still using that name before switching, so the old notifications are removed.

Recover from a broken server plugin

Run on the affected machine. These commands edit config without loading plugin code. Add --config /path/to/config.json for a custom config.

Offline plugin recovery
Command Effect
pi-web plugins disable <plugin-id> --restart Persist disablement; rejects required Terminal.
pi-web plugins safe-start show Inspect safe-start state.
pi-web plugins safe-start set bundled-only --restart Skip external server packages; keep bundled plugins.
pi-web plugins safe-start set none --restart Skip all server plugins, including Terminal; keep diagnosis/Settings surfaces.
pi-web plugins safe-start clear --restart Restore normal configured discovery.

Restart caution: --restart acts only for a recognized safe installation and can interrupt sessions. Config is saved first; follow manual guidance if restart fails.

Server plugins are trusted in-process code, not crash-isolated. Plugin guide →

Fleet compatibility and unavailable plugin UI
  • Upgrade the gateway and target together; mixed-version plugin operation is unsupported.
  • Restart updated web/API processes and target sessiond, then reload the browser.
  • A paired UI is withheld when its package/settings do not match running server code, or the server plugin is unhealthy/incompatible.

Changing directories or running a second instance
  • State migration: a new PI WEB data directory starts with empty registries and no archives. Stop PI WEB before copying state. For archives, copy both archived-sessions.json and archived-sessions/.
  • Second instance: use a distinct data directory, daemon endpoint, and web port. One live session daemon owns each data directory.
  • Agent state: uses the bundled Pi SDK’s data layout. PI WEB does not convert profiles or move PI WEB-managed archives when the agent directory changes.
  • Active paths: changing Pi state or session paths requires a sessiond restart; web/API-only restarts do not apply it. Sessions, terminals, and package operations use the daemon’s active paths. If those paths are unavailable, profile-dependent operations are unavailable too.
Environment inherited by agent processes
  • Agent shells, terminals, and child sessions inherit the daemon environment, including its Pi state paths.
  • NODE_ENV and PORT are removed so they do not interfere with development commands.
  • PI_WEB_SESSION=1 marks nested processes. Inherited PI_WEB_* values still point to the hosting instance. Use a separate data directory, daemon endpoint, and web port for a second instance.
  • Do not restart the hosting session daemon from inside an active session you need to preserve.
  • environmentFacts includes nesting and deployment guidance in session system prompts by default. Set it to false, or use PI_WEB_ENVIRONMENT_FACTS=false, to omit that guidance. Restart sessiond after changing it.

Failed catalog refreshes keep the last successful catalog and report problems in daemon logs. A refresh can briefly delay session startup; the activity line reports when model lists are refreshing.

Pi virtual models are unsupported, including from global extensions. Disable the extension’s virtual-model feature and select a physical model instead; restarting the daemon does not enable virtual models.

Provider safety and logging
  • Provider registrations/configuration are a startup snapshot. /reload cannot rebuild it.
  • Accepted model-list updates are machine-wide; if two workspaces register lists for one provider, the last registration wins.
  • Model entries can override provider URLs/headers. Pi extensions remain trusted code; this is not a security boundary.
  • Provider decisions are recorded in daemon logs, not browser notifications. Entries omit provider configuration and credentials. See provider extension troubleshooting for ignored changes.
