Make PI WEB fit your work

  • Review in one place. Bring findings, checks, and actions into a panel beside your conversation.
  • Connect your tools. Start work in another service and bring progress and results back.
  • See more than text. Add diagrams, media previews, and custom views of tool results.
  • Make routine work repeatable. Add task shortcuts or workflows that use your agents.

For example, build a review panel that starts a Pi conversation and brings its findings back for you to inspect. Browse community plugins for more ideas.

Build your own

Describe the workflow you want to an agent. You do not need to choose APIs or write code. Copy this prompt and replace the last line:

Plugin prompt
You're building a PI WEB plugin. Start with the documentation:
https://pi-web.dev/plugins.md

Here's what I want:
[Describe your plugin]

The documentation leads the agent to supported APIs and working examples.

Install and manage

  1. Open Settings → Pi packages and install the package by its npm name, git/URL, or local source.
  2. Open Settings → PI WEB plugins to check its status and enable or disable its web integration.
  3. Follow the reload or restart guidance shown there.

Browser-only changes need a page reload. By default, server-backed changes need a restart of the target session daemon, then a page reload. A daemon restart can interrupt active sessions and terminals. Check active work first. Reloading the page or using Pi's /reload does not activate server-plugin changes.

Relays, Workflows, Session naming, and MCP manager are included automatically. Remove packages you do not need in Settings → Pi packages; restore them from Available packages.

Upgrading after removing a bundled package

Older command-line or manual removals may receive one last automatic reinstall. Remove the package again to keep it absent. See package provisioning and migration for details.

MCP manager

Connect your agents to external tools and data through the MCP tab. Connections follow the selected machine and also work in Pi’s terminal interface.

Disabling the web plugin hides its controls but leaves server connections active. To stop loading them, remove the package and reload idle sessions. Connection settings and trust →

More included and optional tools

  • Session naming names conversations from their first prompt. Customize naming.
  • Scheduled agent tasks (beta) lets an agent schedule work for later and shows its execution history. Setup and limits.
  • Private input lets you save a secret to a new file without putting its value in the conversation. Setup and privacy boundaries.

Scheduled tasks and Private input are optional: install them from Available packages and enable their web plugins.

Packages, extensions, and plugins

A Pi package is an installable bundle. A Pi extension changes agent behavior; a PI WEB plugin adds web tools. One package can include both. Disabling its web plugin leaves its extensions, skills, and prompts available.

Plugin configuration

Enable or disable plugins in Settings. Other options depend on the plugin and may need a config-file change. Ask your agent to follow the configuration reference. Do not store secrets in generic plugin settings.

Remote machines

Installation and settings apply to the machine selected in Settings. A remote plugin runs its server work there and shows its UI in your browser. Keep gateway and remote PI WEB versions compatible.

Trust and recovery

Install only plugins you trust. Plugins are not sandboxed: they can run code in your browser or access files, environment variables, and processes on their machine. Faulty server plugins can affect other sessions.

Model-backed features may send data to a model provider. Check the plugin's description before using it with sensitive content.

If a plugin fails, check its status in Settings → PI WEB plugins on the affected machine. Disable it there if needed. If the UI cannot recover, use the offline disable and safe-start commands.
